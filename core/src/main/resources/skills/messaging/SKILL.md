## Entry

First work out whether the user wants to read, draft or send, and in which app and account. If the user names an app, use that app; if it won't open or isn't signed in, tell the user plainly.

## Steps

1. **Read**: start from the conversation list or inbox, open the right conversation and read the messages; scroll up for earlier history when needed, noting sender, time, group members and attachments. Unread counts are the red dots and numbers in the list.
2. **Find the recipient**: find them by saved name, nickname, group name or email address. When contacts, groups or channels share a name, open the profile to check. Use real email addresses from contacts or past mail.
3. **Draft**: write it the way the user means. If the user only wants a draft, give them the draft and stop there; if they want it sent, send it once written without asking first.
4. **Send**: open the right conversation or compose page, enter the text, add attachments, and check the recipient and the full text once more before sending.
5. **Check**: after sending, find the message bubble in the conversation, or the email in Sent, and look for any failed-to-send marker.

## Pitfalls

- Search results often contain several people with the same name and different avatars or saved names; tapping the wrong one sends to the wrong person.
- An empty input box does not mean the message was sent; on a poor network a message can stay at "Sending" or show a red exclamation mark. If you don't see it sent, check its status in the conversation before deciding to resend, so it isn't sent twice.
- With some keyboards Enter sends immediately; use the newline key or enter multi-line text in parts.
- The preview in the conversation list is only the beginning, not the full text.

## Done when (evidence to verify)

Reading: the points and times you give come from the opened conversation or email body. Sending: the sent message is visible in the conversation, or the email is in Sent, with the right recipient and content.

## When to stop and hand over

Hand over to the user when sign-in or a verification code is needed, or when the recipient or content has more than one plausible choice and the user must pick.
